# Architecture Decision Records

Create a numbered ADR only for a real decision supported by an Issue. Use the next unused `NNN-short-title.md`; do not manufacture accepted decisions or empty ADR files.

Each ADR must contain: title/number, status, context, linked Issue/PR, options, trade-offs, proposed decision, evidence with sources and dates, security/privacy impact, remaining uncertainties, required validation and recovery/migration implications.

Statuses: PROPOSED, DEFERRED, BLOCKED, ACCEPTED, SUPERSEDED. ACCEPTED requires sufficient evidence and explicit maintainer approval recorded in the Issue/PR. Preserve prior rationale and link superseding decisions rather than rewriting history.

Candidate decision topics (not accepted ADRs): desktop framework; agent runtime placement; native macOS integration; persistence; provider/credentials; approval model; distribution; background execution.
